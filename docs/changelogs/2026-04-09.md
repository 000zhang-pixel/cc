# Changelog 2026-04-09

## 概览

本次改动修复了 middleware 启动崩溃的连锁 bug，并优化了图文内容生成质量：
- 各分组文案场景差异化（不再完全重复）
- 图片子提示词加入真人人物描述
- 场景分配增加随机起始偏移（不再第一组固定最高权重场景）
- B方案：标题写作指南字段注入，支持爆款标题配置

## 2. `db/alembic/env.py`

**改动：为 `fileConfig()` 调用添加 `logging.root.handlers` 守卫**

```python
# 改前
if config.config_file_name is not None:
    fileConfig(config.config_file_name)

# 改后
if config.config_file_name is not None:
    import logging
    if not logging.root.handlers:
        fileConfig(config.config_file_name)
```

**原因：** Alembic 的 `fileConfig()` 默认 `disable_existing_loggers=True`，会清除 middleware 启动时已配置的 `RotatingFileHandler`，导致 `run_migrations()` 执行后所有后续 INFO 日志丢失（只剩 console，不写文件）。守卫确保仅在 Alembic CLI 直接调用时（root 尚无 handler）才执行 fileConfig。

```python
run_migrations()
# 重新挂载 RotatingFileHandler（防止 alembic fileConfig 清除后日志丢失的双重保险）
_log_file = Path(__file__).parent.parent / "logs" / "middleware.log"
_root = logging.getLogger()
_root.setLevel(logging.INFO)
if not any(
    isinstance(h, logging.handlers.RotatingFileHandler) for h in _root.handlers
):
    _fh = logging.handlers.RotatingFileHandler(
        filename=_log_file, maxBytes=10 * 1024 * 1024, backupCount=5, encoding="utf-8"
    )
    _fh.setFormatter(logging.Formatter(
        "%(asctime)s [%(levelname)s] %(name)s: %(message)s", datefmt="%Y-%m-%d %H:%M:%S"
    ))
    _root.addHandler(_fh)
```

**原因：** 作为 env.py 守卫的双重保险。即使 fileConfig 清除了 handler，main.py 在迁移后会重新挂载，保证日志文件完整。

### 4b. `_build_text_prompts_from_strategy`：新增 `scene` 参数 + 场景块注入（~606 行）

**改动：** 增加 `scene: dict | None = None` 参数，从场景记录中提取 `场景描述_中文` 和 `风格基调词`，构建 `scene_block` 注入到 user_prompt。

```python
# 新增参数
def _build_text_prompts_from_strategy(
    ...,
    scene: dict | None = None,
) -> tuple[str, str]:

# 新增场景块
scene_block = ""
if scene:
    scene_desc = scene.get("场景描述_中文", "")
    scene_style = scene.get("风格基调词", "")
    parts = [p for p in [scene_desc, scene_style] if p]
    if parts:
        scene_block = f"\n\n场景设定（请将内容植入此场景氛围中）：{'｜'.join(parts)}"

# 注入到 user_prompt
f"产品信息：\n{sku_summary}{scene_block}\n\n"
```

**原因：** 同一任务不同分组的文案内容完全重复（均由相同的 sku_summary + system_prompt 生成）。通过将每组分配到的场景描述注入到 user_prompt，驱动 LLM 产出差异化文案。

### 4c. `_build_text_prompts_from_strategy`：标题写作指南注入（B方案，~646 行）

**改动：** 读取表8策略记录中的 `标题写作指南` 字段，注入到输出格式的标题部分。

```python
# 新增
title_guide = f.get_text(strategy, "标题写作指南").strip()
title_instruction = (
    f"<标题（≤20字）>\n参考方向：{title_guide}" if title_guide else "<标题（≤20字）>"
)

# 替换原硬编码格式
f"输出格式：\n【标题】\n{title_instruction}\n\n【正文】\n<正文（{word_count}）>"
```

**原因：** 生成的标题平铺直述，无爆款感。B方案：在表8策略记录中配置「标题写作指南」字段（含爆款公式、禁忌等），由代码读取后注入到每条策略的 user_prompt，实现「改策略不改代码」。字段未填时降级为原格式，不影响已有逻辑。

**用户操作：** 需在飞书表8对应策略记录中新建 `标题写作指南`（多行文本）字段并填写，例如：
```
公式选一：①数字冲击（"3秒让手机链颜值×10"）②场景痛点（"出门总被问链子哪买的"）③反转悬念（"以为只是条链子，没想到…"）
要求：含emoji或符号、口语化、禁止平铺产品描述
```

### 4e. `_build_image_sub_prompts`：新增 `person_suffix` 人物描述（~740 行）

**改动：** 从场景对象中读取人物字段，构建 `person_suffix` 附加到每张子提示词末尾。

```python
person_type = scene.get("人物类型", "").strip()
_no_person_types = {"无人物", "纯产品", ""}
if person_type and person_type not in _no_person_types:
    gender  = scene.get("性别倾向", "").strip()
    age     = scene.get("年龄段", "").strip()
    appear  = scene.get("外貌风格", "").strip()
    posture = scene.get("姿态倾向", "").strip()
    person_attrs = "、".join(x for x in [gender, age, appear, posture] if x)
    person_suffix = f"，画面中有{person_type}" + (f"（{person_attrs}）" if person_attrs else "")
else:
    person_suffix = ""

# 应用到每张子提示词
f"第{i + 1}张：{zh_text}{scene_suffix}{person_suffix}"
```

**原因：** 图片生成几乎没有真人出镜。master prompt 中有 `【人物】` 块，但 sub-prompts 只有镜头角色和场景描述，AI 倾向于省略真人。通过在每张子提示词末尾明确追加人物描述，强制每张图都包含真人要求。

### 4f. `_assign_scenes`：随机起始偏移（~568 行）

```python
# 改前
for i, g in enumerate(groups):
    scene = pool[i % len(pool)]

# 改后
start = random.randrange(len(pool))   # ← 新增
for i, g in enumerate(groups):
    scene = pool[(start + i) % len(pool)]
```

**原因：** `pool` 按权重降序排列，`pool[0]` 始终是最高权重场景（木质桌面+咖啡杯）。每次任务第一组都分配到同一场景。加入随机起始偏移后，每次任务的第一组从 pool 中随机位置开始，实现真正轮转。

## 6. `middleware/handlers/content_generation.py`：子提示词一致性约束注入（~801 行）

**改动：** 在 `_build_image_sub_prompts` 中，为有人物的场景，在每张子提示词末尾追加一致性锚定文字。

```python
# 新增（person_type 不为空/无人物时）
consistency_note = (
    "，【一致性约束】本组所有图片为同一人物："
    "保持完全相同的服装（颜色/款式/细节）、相同发型、相同面孔特征，禁止更换服装或人物"
)
# 应用到每张子提示词末尾
f"第{i + 1}张：{zh_text}{scene_suffix}{person_suffix}{consistency_note}"
```

**原因：** 同一组的4-6张图片中，人物服装和长相不一致（每张图独立生成，AI 不知道要保持一致）。通过在每张子提示词末尾明确追加一致性约束，强制图片生成模型对每张图都遵守同一人物设定。无人物场景 `consistency_note` 为空字符串，不影响纯产品图。
