# Changelog 2026-05-08

## 概览

修复 AI-CONTENT middleware 中 `plans` 本地镜像状态与飞书远端状态长期不一致的问题。

具体表现为：飞书《内容规划表》中的计划任务已经执行完成，但本地 SQLite `plans` 表仍停留在 `待执行`，导致排障和状态判断出现“双真相”。

本次修复采用**最小改动策略**：不推翻“状态字段本地权威”的整体设计，只对 `Plan` 在同步阶段增加**远端完成态/失败态的定向收敛**。

---

## 问题现象

以规划编号 `T_260507_109` 为例：

- 飞书远端记录显示：
  - `确认执行 = 是`
  - `执行状态 = 完成`
  - `任务完成时间` 已写入
  - `任务日志` 已写入
- 本地 SQLite `plans` 表却仍显示：
  - `exec_status = 待执行`
  - `confirmed_exec = 0`

这会造成两个问题：

1. 排障时误判为“任务没有被 poller 消费”
2. 本地数据库无法正确反映已完成计划的真实状态

---

## 根因

`db/sync/syncer.py` 现有策略中，以下字段被定义为 **local-authoritative**，同步时不会被飞书覆盖：

- `exec_status`
- `confirmed_exec`
- `started_at`
- `finished_at`
- `error_msg`

同时，`_map_plan()` 也明确未映射 `执行状态`。

因此只要计划任务先在远端被推进到 `完成/失败`，本地已有记录就不会自动收敛，状态会长期陈旧。

---

## 代码修复

### 文件

- `db/sync/syncer.py`
- `tests/test_sync_strategy.py`

### 调整内容

在 `FeishuSyncer` 中新增 `Plan` 专用状态收敛逻辑：

1. 保持原有“非状态字段正常同步”的流程不变
2. 在已存在的 `Plan` 记录更新路径中，追加一次 `_reconcile_remote_plan_state(existing, raw)`
3. 仅对 `Plan` 做以下定向收敛：
   - 远端 `执行状态=完成` → 本地 `exec_status=完成`
   - 远端 `执行状态=失败` → 本地 `exec_status=失败`
   - 远端 `执行状态=执行中` 且本地仍为 `待执行` → 推进为 `执行中`
   - `确认执行=是/立即执行` → 本地 `confirmed_exec=True`
   - `任务完成时间` → 本地 `finished_at`
   - `任务日志` → 本地 `error_msg`

### 关键实现点

新增两个辅助函数：

- `_plan_confirmed()`
- `_plan_status()`

新增一个最小专用方法：

- `_reconcile_remote_plan_state()`

该方法只作用于 `Plan`，不扩散到 `Content / PublishRecord / Material`，避免范围蔓延。

## 影响范围

- 计划表 `Plan` 的本地状态在远端完成/失败后可自动收敛
- 降低排障时“飞书已完成 / 本地仍待执行”的误判概率
- 不改变 poller 触发规则
- 不改变 content / publish / material 的现有状态同步策略
