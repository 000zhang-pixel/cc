# 仓库与工作区路径规范

**日期**: 2026-04-18  
**状态**: 已采用

---

## 1. 目标

为 AI-Content-Hub 建立一个对工具中立、跨电脑可复用、便于多人/多代理协作的标准仓库路径规范。

适用场景：
- 同一套系统会被 Hermes、Claude Code、OpenClaw 等多个工具共同管理
- 代码需要在多台电脑之间同步与继续开发
- 文档、PRD、脚本、代码需要保持单一事实源

---

## 2. 决策

### 2.1 GitHub 是唯一事实源

正式代码、PRD、运维脚本、设计文档统一以 GitHub 仓库为准：

- 仓库：`https://github.com/000zhang-pixel/cc`
- 不允许只在某个本地 backup 目录保留“最新版本”文档
- 任何需要长期保留和跨设备复用的文档，都应提交到仓库

### 2.2 每台机器只保留一个“主工作副本”

macOS 上的标准主工作副本路径：

```bash
~/workspace/ai-content-hub
```

说明：
- Hermes、Claude Code、OpenClaw 等工具都应优先操作这个路径
- 其他路径下的副本仅允许作为临时备份或归档，不应继续并行开发

### 2.3 工具工作目录与项目代码目录分离

以下目录职责分离：

- `~/workspace/ai-content-hub` → 项目主仓库（受 Git 管理）
- `~/.hermes/` → Hermes 配置、缓存、记忆、运行态文件
- `~/.claude/` / `~/.claude.json` → Claude Code 相关配置
- `~/agent-workspace/` → agent 编排脚本、监控脚本、临时实验、历史备份

原则：
- **项目代码不要长期放在工具私有目录下**
- **工具状态文件不要混入项目仓库**

### 2.4 跨平台路径采用“配置可覆盖 + 仓库路径稳定”原则

不同机器或系统可有不同运行配置，但仓库路径命名应尽量稳定、可预测。

建议：
- macOS：`~/workspace/ai-content-hub`
- Windows：`D:/AI-Content-Hub` 或统一的团队约定路径

已有代码中若存在平台路径常量，可逐步清理，但不要求一次性重构。

---

## 3. 执行规范

### 3.1 新文档落盘规范

以下内容必须直接写入主仓库：
- PRD
- 架构决策
- 运维操作说明
- 重要脚本说明
- 影响后续开发的方案文档

推荐目录：
- `docs/prd/`
- `docs/decisions/`
- `docs/changelogs/`

### 3.2 多工具协作规范

当同一仓库会被多个工具共同操作时：

1. 所有工具统一打开同一个主副本路径
2. 不在多个本地副本上并行修改同一模块
3. 开始工作前先 `git pull`
4. 完成稳定改动后及时 `git add/commit/push`
5. 临时 backup 目录不作为新的事实源

### 3.3 本地备份规范

允许保留本地备份目录，但必须满足：
- 目录名明确体现 backup / archive / snapshot 属性
- 默认只读使用，不继续作为主开发目录
- 如需恢复，以 Git 历史或明确的文件对比为准，不靠人工记忆判断“哪个最新”

---

## 4. 当前迁移结论

本机已将 AI-Content-Hub 的主工作副本标准化到：

```bash
~/workspace/ai-content-hub
```

`~/.hermes/cc` 若继续保留，只应作为兼容入口或过渡引用，不应再视为长期主仓库位置。

---

## 5. 后续建议

1. 后续新增 PRD 一律直接写入主仓库
2. 逐步清理仓库内硬编码的绝对路径说明
3. 将虚拟环境、运行产物、缓存目录完整加入 `.gitignore`
4. 若有第二台电脑，也采用同样的“一个主副本 + GitHub 同步”策略

---

## 6. 一句话原则

> **主仓库放在中立工作区，工具围绕仓库工作，而不是让仓库依附某个工具。**
