# AI 内容创作与发布系统 — 产品需求文档 (PRD)

**版本**: v0.4
**最后更新**: 2026-04-04
**状态**: 阶段五-C（智能提示词引擎）+ 阶段六（得物自动发布集成）已完成

---

## 一、项目背景

电商卖家（得物/小红书），主要品类：手机壳、手机挂架，后续拓展更多品类和平台。

目标：借助飞书多维表格 + 本地中台，构建 AI 内容批量创作与自动发布系统，实现大规模高质量种草图文和视频的创作，提升曝光与引流效率。

---

## 二、系统整体架构（7层）

```
① SKU信息表          ← 产品数据根基
② 内容规划表         ← 每次批量生成任务的配置
③ 提示词生成表       ← 4种Prompt类型的生成记录
④ 内容生成表         ← 每个内容单元（标题+正文+标签+图/视频）
⑤ 发布执行表         ← 审核后安排发布（ADB自动发布或手动）
⑥ 素材知识库         ← 投喂爆款素材，反推提示词，持续优化
⑦ 标签库             ← 各平台热门标签，权重评分，动态注入内容

智能提示词引擎（三层查表驱动）：
⑧ 内容策略表(Strategy)  ← 切入角度 + 情绪基调 + 文案叙事节点
⑨ 拍摄方案表(ShotPlan)  ← 分镜角色序列（JSON），驱动子Prompt生成
⑩ 视觉场景表(Scene)      ← NANOBANANA场景基底英文 + 风格词 + 排除描述
```

**本地中台**负责：监听飞书表格变更 → 调用AI API → 写回生成结果

## 七、编码规则体系（已确认）

### 设计原则

- 日期精确到日：`YYMMDD`（6位）
- 子记录继承父级ID：内容生成、发布执行的ID嵌入任务ID，天然可溯源
- 组号区分图文/视频：`img01`、`vid01`
- Prompt用后缀区分类型：`_C`（文案）、`_I`（图像/视觉生成）

### 各表编码格式

| 表 | 格式 | 示例 |
|---|---|---|
| 表2 内容规划表 | `T_YYMMDD_XXX` | `T_260329_089` |
| 表3 提示词生成表 | `P_[规划ID]_[组号]_[C/I]` | `P_T_260329_089_img01_C` |
| 表4 内容生成表 | `[规划ID]_[组号]` | `T_260329_089_img01` |
| 表5 发布执行表 | `Pub_YYMMDD_XXX_[组号]` | `Pub_260329_089_img01` |
| 表6 素材知识库 | `SM_YYMMDD_XXX` | `SM_260329_002` |
| 表7 标签库 | `Tag_YYMMDD_XXX` | `Tag_260329_001` |

### 提示词类型后缀

| 后缀 | 含义 | 适用组 |
|---|---|---|
| `_C` | Copy — 文案类Prompt | img / vid |
| `_I` | Image/Visual — 生成类Prompt | img / vid |

### ID 层级关系

```
T_260329_089                          ← 内容规划
├── P_T_260329_089_img01_C/I          ← 图文组Prompt
├── P_T_260329_089_vid01_C/I          ← 视频组Prompt
├── T_260329_089_img01                ← 图文内容
│   └── Pub_260329_089_img01          ← 发布执行
└── T_260329_089_vid01                ← 视频内容
    └── Pub_260329_089_vid01          ← 发布执行
```

## 八、表流转与触发逻辑

### ✅ 表2：内容规划表

#### 输入

**用户必填**

| 字段 | 说明 |
|---|---|
| 关联SKU | 决定产品属性来源 |
| 任务类型 | 决定后续哪些模型字段必填 |
| 内容类型 | ≥1种，多选时中台随机分配给各组 |
| 目标平台 | ≥1个，多选时生成一份内容通用多平台 |
| 文案模型 | 所有任务类型均需 |
| 确认执行 | 唯一触发开关 |

**条件必填**（中台校验，缺失则拒绝执行并写入日志）

| 条件 | 必填字段 |
|---|---|
| 任务类型 = AI全创作 且 图文篇数 > 0 | 图片模型 |
| 任务类型 = AI全创作 且 视频篇数 > 0 | 视频模型、视频最短/最长时长 |
| 视频篇数 > 0（任意任务类型） | 视频最短/最长时长 |

> 字段默认值统一在飞书多维表格侧配置，中台不重复管理。

#### 触发条件

```
监听：确认执行 变更为「是」
前置校验（任一不满足 → 拒绝执行，写入日志，状态改「失败」）：
  ① 关联SKU 已填
  ② 关联SKU 对应记录满足 SKU数据完整性要求：
       - SKU编号、SKU名称、产品简称、白底图、品类 均已填写
       - 卖点1 已填写（至少有第一条卖点）
       - 上架状态 = 已上架
     （任一不满足 → 拒绝执行，提示：「SKU数据不完整或未上架，请先完善SKU信息」）
  ③ 任务类型 已选
  ④ 目标平台 已选
  ⑤ 内容类型 已选（≥1）
  ⑥ 文案模型 已选
  ⑦ 条件必填字段满足
  ⑧ 执行状态 ≠ 执行中（防重复触发）
```

#### 触发后中台执行流程

```
① 执行状态 → 执行中
② 读取表2所有配置字段
③ 从表1（SKU信息表）读取产品属性
④ 从表7（标签库）按「平台 + 品类」取 TOP N 启用标签
⑤ 按图文篇数创建 img01…imgXX 组
   按视频篇数创建 vid01…vidXX 组
   每组从「已选内容类型」中随机分配一种
⑥ 每组写入表3（提示词生成表）× 2条记录（_C + _I）
⑦ 调用 Prompt 引擎生成各组提示词，回写表3
⑧ 调用 AI API 执行生成，写入表4（内容生成表）
⑨ 全部完成 → 执行状态「完成」，写入任务完成时间
   任一失败 → 执行状态「失败」，写入失败原因至任务日志
```

### ✅ 飞书监听机制（已确认）

#### 两阶段方案

```
第一阶段（开发调试期）：轮询（Polling）

```

#### 整体结构

```
┌─────────────────────────────────────────┐
│              Poller（轮询器）              │
│  每10秒查询飞书 API                       │
│  → 检测各表触发条件                       │
│  → 封装成标准 Task 对象                   │
│  → 推入任务队列                           │
└──────────────┬──────────────────────────┘
               ↓
┌─────────────────────────────────────────┐
│           Task Dispatcher（分发器）       │
│  按 task_type 路由到对应 Handler          │
└──────┬──────────┬──────────┬────────────┘
       ↓          ↓          ↓
  生成Handler  搬迁Handler  分析Handler …
```

#### 各表触发条件

| 表 | 触发条件 | Handler |
|---|---|---|
| 表2 | 确认执行=是 AND 执行状态=待执行 | `ContentGenerationHandler` |

| 表6 | 触发分析=是 AND 分析状态=待分析 | `MaterialAnalysisHandler` |

#### 防重复处理

轮询发现触发记录后，**第一个动作**立即将状态字段更新为「处理中」：

```

```

## 十二、得物自动发布集成（阶段六）

### ✅ 架构设计（已完成，2026-04-04）

#### 整体链路

```
表5「发布方式」→「得物自动发布」
  ↓ 中台 PublishHandler
  ① 从飞书表5读取发布记录，获取关联内容记录的内容编号
  ② _parse_content_code 解析：T_260404_016_img01 → plan_code=T_260404_016 / group_id=img01
  ③ 从本地 workspace 读取内容文件（title.txt / body_tags.txt / img_*.jpg / video.mp4）
  ④ 整理为 V4.0 content-store 格式，写入：
       {ai-content-system}/content-store/ready/{YYMMDD}/{内容编号}/
         images/01.jpg … 05.jpg（或 01.mp4）
         title.txt
         content.txt（正文+标签）
         metadata.json
  ⑤ 更新表5「发布状态」→「发布中」
  ⑥ 调用 bash publish_engine_v40.sh single <发布编号> <内容编号>
       环境变量：AI_CONTENT_SYSTEM_DIR = content_store_dir
       PATH 注入：C:\platform-tools（ADB所在目录）
  ⑦ 脚本 ADB push 图片到手机 → 自动操控得物 App → 发布
  ⑧ exit code 0 → 表5「发布状态」=「已发布」+ 写入实际发布时间
     非0 → 表5「发布状态」=「发布失败」+ 写入失败日志（stderr最后500字）
```

#### 配置项（system.yaml）

```yaml
publish:

    engine_script: "/c/Users/carson/Desktop/workspace/workspace/ai-content-system/modules/mobile-publisher/scripts/publish_engine_v40.sh"
    content_store_dir: "/c/Users/carson/Desktop/workspace/workspace/ai-content-system"
```

- 位置：`ai-content-system/modules/mobile-publisher/scripts/publish_engine_v40.sh`

## 十一、飞书表格 API 创建脚本

### ✅ 设计方案（已完成，10张表）

#### 目标

用 Python 脚本通过飞书 API 自动创建 10 张多维表格及全部字段、关联关系，支持幂等重跑。

#### 语言与 SDK

Python + 官方 `lark-oapi` SDK。

#### 建表顺序（按依赖关系）

| 顺序 | 表名 | 依赖 |
|---|---|---|
| 1 | 表1 SKU信息表 | 无 |
| 2 | 表7 标签库 | 无 |
| 3 | 表6 素材知识库 | 无 |
| 4 | 表2 内容规划表 | 关联表1 |
| 5 | 表3 提示词生成表 | 关联表2、表1 |
| 6 | 表4 内容生成表 | 关联表3、表2 |
| 7 | 表5 发布执行表 | 关联表4 |
| 8 | 表8 内容策略表 | 无 |
| 9 | 表9 拍摄方案表 | 无 |
| 10 | 表10 视觉场景表 | 无 |

#### 幂等策略

```
建表前：查询 Base 现有表名 → 名称匹配则跳过，记录日志
建字段前：查询表现有字段名 → 名称匹配则跳过，记录日志
关联字段：目标表不存在时报错中止（依赖顺序保证不会发生）
```

#### 项目结构

```
scripts/
  setup_base.py          # 主入口，按顺序调用
  tables/
    definitions.py       # 7张表字段定义（Python dict）
    relations.py         # 关联字段配置
  lib/
    lark_client.py       # 飞书 API 封装（建表、建字段、查询）
```

#### 运行方式

```bash
python scripts/setup_base.py --app-token <BASE_APP_TOKEN>
```

`app_token` 从命令行传入，不硬编码。
