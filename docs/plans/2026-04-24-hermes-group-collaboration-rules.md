# Hermes 总裁办群协同群规（2026-04-24）

> 目的：把群内多 agent 的日常协同动作，收敛成简明、刚性的群规，供 Hermes_CEO / 大T_技术总工 / 大C_内容总监 / 后续新增 agent 长期遵守。

---

## 1. 总则

1. `Hermes_CEO` 是群内唯一总控与正式收口出口。
2. 一个任务只能有一个主责 agent；没有 owner，不开工。
3. 正式协同只认：`wrapper → verified mention → receipt`。
4. 无真实 mention、不走 wrapper、无 receipt，均不算正式消息。
5. 群内只同步：结论、状态、动作、责任，不展开冗长内部推理。

---

## 2. 8+1 正式消息类型

- `【受理】`：默认由 Hermes_CEO 接住总任务；专业 owner 也可正式接住其子任务
- `【派单】`：默认由 Hermes_CEO 发总控派单；当前 owner 也可在授权范围内向下游正式派单
- `【接单】`：主责 agent 接手
- `【进展】`：主责 agent 同步状态
- `【风险】`：主责 agent 或 Hermes_CEO 上报阻塞 / 冲突
- `【交付】`：主责 agent 回交结果
- `【催办】`：Hermes_CEO 追时效、追责任
- `【结论】`：Hermes_CEO 做阶段 / 最终收口
- `【仲裁】`：仅用于纠偏，不用于补普通派单

固定流程：
`【受理】 → 【派单】 → 【接单】 → 【进展】/【风险】 → 【交付】 → 【结论】`

---

## 3. 主责与 @ 规则

1. 一条正式消息只能有一个当前 owner。
2. `【派单】` 的第一真实 mention = 主接单对象。
3. 其他 mention 只能是协作知会或收口抄送。
4. 需要给协作对象下任务，必须另发一条独立 `【派单】`。
5. 正式责任字段必须使用群内真实显示名，不能写 profile 名。
6. 即使两个人收到的是同样内容，只要它们代表两条独立责任，也必须拆成两条正式消息分别发送，不得在一条 `【派单】` / `【催办】` / `【仲裁】` 里把两人并列写成 owner。
7. 一条消息里可以多 @，但前提是 owner 仍然唯一；其余 @ 只能承担“协作知会”或“收口抄送”，不能形成并列责任。
8. 如果诉求只是统一提醒、公告、同步，而不是正式追责/派单，可使用日常消息或单 owner 正式消息 + 其他对象知会，不要把“群通知”误发成“多人并列正式催办”。

---

## 4. 标签纪律

1. `【受理】` 只用于接住需求，不代替 `【派单】`。
2. 只要是执行单 / 协作单 / 正式任务分配，必须使用 `【派单】`。
3. `【仲裁】` 只用于纠偏；标签错了就重发正确标签，不用 `【仲裁】` 补细节。
4. 一个动作对应一个标签，不混用。

---

## 5. 首响与过程纪律

1. 正式派单 / 催办 / 仲裁成立后，主责 agent 必须先首响，再补长文。
2. 常规任务 30 秒内至少形成 `【接单】` 或短 `【进展】`。
3. 有阻塞必须主动发 `【风险】`，不能静默。
4. 同一阶段连续 2 次 `【进展】` 仍未收口时，优先阶段交付并由 `Hermes_CEO` 发 `【结论】`。

---

## 6. 正式消息之外的日常沟通规则

1. 群内除 9 类正式消息外，日常沟通统一使用半结构化标签：`〔同步〕/〔求助〕/〔确认〕/〔补充〕/〔提醒〕/〔复盘〕`。
2. 日常消息不得使用 `【】` 正式标签，避免伪正式。
3. 日常消息默认控制在 3~6 行，一条只承载一个主题或一个动作。
4. 日常消息里的 @ 仅表示提醒或拉人看，不自动形成正式交接。
5. 若内容已涉及 owner 成立、交付成立、阶段收口、风险升级，必须升级为 9 类正式消息。
6. 具体模板与升级规则见：`docs/plans/2026-04-24-hermes-daily-message-style-guide.md`

---

## 7. 排版纪律

1. 正式消息优先使用短列表结构，避免大段整块文字。
2. 一级信息用 `-`，步骤项 / 时间点 / 交付项用 `1. 2. 3.`。
3. 一条正式消息优先控制在 4~8 行核心内容。
4. 日常半结构化消息优先控制在 3~6 行，尽量一屏内读完。
5. 可适度使用 emoji 提升辨识度，但必须克制、专业。
6. 不得为了排版美观牺牲责任、时点、owner 和 receipt 的清晰度。

---

## 8. 禁止事项

- 两个 agent 同时发布不同版本最终结论
- 未明确主责就多人并行输出正式结论
- 没有真实 @ 的伪派单
- 没有 receipt 就宣称正式完成
- 非 `Hermes_CEO` 越级发布跨 agent 正式综合结论
- 在一条 `【派单】` 里设置多个 owner

---

## 9. 冒烟测试与抽检

1. 新 agent 入群前后必须完成 3 条 smoke test：`【接单】` / `【进展】` / `【交付】`。
2. 已在岗 agent 也必须接受周期性抽检。
3. 抽检只认回执和回读证据，不认肉眼判断。
4. 抽检不通过时：先纠偏、再补测，通过后方可恢复正式协同。

---

## 10. 执行结论

本群长期执行口径：
- 正式消息必须合规
- 协同必须可观察
- 责任必须可追溯
- 收口必须由 Hermes_CEO 统一完成
