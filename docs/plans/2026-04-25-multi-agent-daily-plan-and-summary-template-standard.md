# Hermes 多 Agent 每日工作规划 / 工作总结统一模板规范

## 1. 目标

把群里效果已验证的“工作规划/工作汇报”写法，沉淀为 `default / 大T_技术总工 / 大C_内容总监` 可复用的统一模板。

适用场景：
- 每日工作安排
- 每日工作总结
- 阶段性工作梳理
- 日终收口前的当日回顾

目标不是把所有日常消息都写长，而是让**需要结构化同步的日常工作消息**保持统一、可扫读、可比较、可复核。

---

## 2. 使用原则

1. **优先结构清楚，不追求花哨。**
2. **先写主线判断，再写今日动作。**
3. **先给结论，再给细节。**
4. **一条消息只覆盖“今日规划”或“今日总结”中的一种，不混写。**
5. **可以适度用 emoji / 分隔线增强可读性，但保持克制、专业。**
6. **若消息已经形成正式责任、正式交付或正式收口，仍需升级为 9 类正式消息，不以日常模板替代。**

---

## 3. 统一输出场景

### A. 每日工作规划
适用于：上午开工、午后重排优先级、收到新任务后统一重排当日安排。

推荐结构：
1. 标题
2. 当前主线梳理
3. 今日工作计划安排
4. 今日验证与节奏安排
5. 风险与注意事项
6. 建议群内同步口径（如需要）

### B. 每日工作总结
适用于：日终总结、阶段收口前回顾、对外汇报当日完成情况。

推荐结构：
1. 标题
2. 今日完成情况
3. 今日关键判断 / 变化
4. 未完成项与原因
5. 明日衔接安排
6. 风险与需要协同项

## 6. 群内卡片化建议

当需要把“每日工作规划 / 总结”发到群里时，推荐优先使用：
- **正式 `【进展】 rich`**：适合“今日工作规划 / 阶段性工作梳理”
- **正式 `【结论】 standard/short`**：适合“日终已形成阶段收口”
- **L2 `〔同步〕`**：适合轻量版每日更新

### `【进展】 rich` 推荐字段口径
- `task_name`：如“<显示名> 今日主线与工作计划”
- `goal`：一句话说明这次同步的目的
- `todo_done_*`：已完成的前置梳理 / 已确认事项
- `todo_pending_*`：今天继续推进的重点动作
- `status`：当前状态
- `deadline`：今日下一关键回报时点
- `next_milestone`：下一个明确节点
- `annex_title / annex_summary / annex_link`：对应当天规划文档

## 7. 对各 Agent 的统一要求

### 对 Hermes_CEO
- 更强调：全局优先级、主线判断、责任与下一步。
- 不展开过细执行细节。

### 对 大T_技术总工
- 更强调：技术主线、验证动作、证据、风险边界。
- 不把“待验证”写成“已完成”。

### 对 大C_内容总监
- 更强调：内容主线、产出结构、文案/策略判断、待协同输入。
- 不把“创意方向”写成“最终定稿”。

---

## 8. 执行要求

自本规范生效后：
1. `default / 大T_技术总工 / 大C_内容总监` 的每日工作规划，优先按本模板输出。
2. 每日工作总结，优先按本模板输出。
3. 若只做极短同步，可降级为 `〔同步〕`，但仍应保留“当前 / 变化 / 下一步 / 时点”四要素。
4. 若形成正式责任或正式收口，必须升级到 wrapper 正式消息，不得只发普通总结。
