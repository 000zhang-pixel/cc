## 背景

手机链类目上线后，新生成内容（如 T_260409_045_img01）出现两个问题：
1. 图片全是极简背景主体产品图，完全没有人物入镜
2. 标题/正文与其他内容重复，策略分化没有起到任何作用

---

## Bug 1 — 图片走了默认兜底，拍摄方案失效

### 根因

`_build_image_sub_prompts()`（`content_generation.py` 第722行）读取角色序列节点时，
硬编码使用 `node.get("zh", "")` 取文字内容：

```python
zh_text = nodes[i].get("zh", "").replace("{scene_description}", scene_zh)
```

但 SP010-SP019 的 `角色序列` 写入飞书时，JSON 格式为：

```json
{"index": 1, "shot": "首图人物全身", "desc": "模特全身出镜，手持手机..."}
```

字段名是 `shot` 和 `desc`，**不存在 `zh` 字段**。结果每张图都拿到空字符串，
触发 `_default_shot()` 兜底，全部走 `_DEFAULT_SHOT_ROLES`：
- 产品正面全景
- 产品细节特写  
- 产品上手使用
- 产品侧后角度
- 产品平铺俯拍
- 产品场景融合

这就是为什么图片全是"极简背景主体图"。

### 修复

兼容多种字段格式：

```python
node = nodes[i]
if node.get("zh"):
    zh_text = node["zh"]
elif node.get("shot") and node.get("desc"):
    zh_text = f"{node['shot']}：{node['desc']}"
elif node.get("shot"):
    zh_text = node["shot"]
else:
    zh_text = ""
```

## Bug 2 — 策略选不中 ST022-ST030，文案没有差异化

### 根因

ST022-ST030 在飞书策略表中，`适用内容类型` 字段值为 `["图文"]`。
而系统实际使用的内容类型枚举（`CONTENT_TYPES`，共12种）中**没有"图文"**：

```python
CONTENT_TYPES = [
    "种草推荐", "好物分享", "深度测评", "对比测评",
    "穿搭搭配", "场景展示", "日常vlog",
    "开箱", "买家秀/晒单", "节日/活动限定", "新品发布",
    "选购攻略/使用教程",
]
```

`_select_best()` 打分逻辑要求 `content_type` 命中才能得分，
"图文" 永远得0分 → ST022-ST030 从不被选中。

系统实际使用的是 ST001-ST020（手机壳策略），这些策略的 `适用品类` 也包含手机链，
所以得分略低但仍能匹配，导致所有手机链内容都在用手机壳文案策略。

### 修复

将 ST022-ST030 的 `适用内容类型` 和 `适用平台` 修正为正确枚举值：

| 编号 | 策略名称 | 内容类型 | 平台 |
|------|---------|---------|------|
| ST022 | 社交货币展示型 | 种草推荐、好物分享 | 小红书、得物 |
| ST023 | 工艺细节深度型 | 深度测评、场景展示 | 小红书、得物 |
| ST024 | 场景生活化沉浸型 | 日常vlog、场景展示 | 小红书、得物 |
| ST025 | 情感价值共鸣型 | 种草推荐、节日/活动限定 | 小红书、得物 |
| ST026 | 平台适配爆款型 | 种草推荐、好物分享 | 小红书、得物 |
| ST027 | 潮流趋势引领型 | 穿搭搭配、种草推荐 | 小红书、得物 |
| ST028 | 选购决策辅助型 | 选购攻略/使用教程、对比测评 | 小红书、得物 |
| ST029 | 真实体验分享型 | 买家秀/晒单、好物分享 | 小红书、得物 |
| ST030 | 品类教育种草型 | 种草推荐、开箱 | 小红书、得物 |

## 复盘：为什么会出现字段名不匹配

历史原因：拍摄方案节点格式最初设计为 `{"zh": "...", "en": "..."}` 双语，
后来写入数据时改用了 `{"shot": "...", "desc": "..."}` 描述性格式，
但代码侧未同步更新。属于数据约定与代码约定脱节的典型问题。

**后续建议**：在 `fix_strategies_and_shotplans.py` 或配置文档中明确约定节点 JSON schema。
