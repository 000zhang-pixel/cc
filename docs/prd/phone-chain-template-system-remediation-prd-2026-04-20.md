## 1. 背景与问题定义

近期对 `T_260420_066` 的三组手机挂链成图进行逐张审查后，确认当前模板系统存在**系统级配置问题**，不是单次抽样偶发问题。

### 1.1 直接触发本次整改的现象

用户明确反馈并经审图复核确认：

- 人物不够精致美丽
- 服装不够时尚
- 运动场景不适合展示手机挂链
- 手机挂链比例与展示逻辑不稳定
- 场景、人物、服装、商品之间缺乏统一带货逻辑

### 1.2 代码与数据审计结论（本次已核实）

对本地导出的四表数据进行审计，手机链相关模板规模如下：

- Scene（适用品类包含手机链）：**87** 条
- Persona（适用品类包含手机链）：**12** 条
- ShotPlan（适用品类包含手机链）：**39** 条

其中发现以下高风险现状：

- 手机链 Scene 中，命中“性感化/腿部曲线/短裙导向”等风险词的记录：**57 条**

## 2. 本次整改目标

### 2.1 总目标

把当前手机挂链模板系统，从“能生成图”升级为“**能稳定生成更适合带货的手机挂链图**”。

### 2.2 必须达成的结果

1. 清理或降权所有明显不适配手机挂链的旧模板
2. 为手机挂链建立独立的模板治理规则，而不是继续复用泛品类模板
3. 建立手机挂链专属的：
   - 策略白名单
   - 场景白名单
   - 人设白名单
   - ShotPlan 白名单
4. 为模板新增或补齐“适配信号”，降低错误匹配
5. 在代码层增加可验证的筛选/审计/验证机制
6. 输出一套可扩展到飞书表的数据整改作业方式

### 2.3 成功标准

整改后，对手机挂链类内容生成应满足：

- 人设、服装、场景之间不再明显互相打架
- 至少 80% 以上模板来自手机挂链专用白名单，不再主要依赖泛模板兜底
- 每组图片中商品可见度和挂接逻辑显著增强
- 跑步、飞扬、双人稀释、错误材质、性感化身体展示等问题显著下降
- 审核时能解释每组内容：
  - 为什么命中该策略
  - 为什么命中该场景
  - 为什么命中该人设
  - 为什么该 shot plan 对手机挂链成立

## 3. 本次整改原则

## 3.1 商品优先原则

对于手机挂链：

- 商品必须是画面中的**可识别主角之一**
- 不是“人物氛围图里顺带出现一个挂链”
- 不是“场景主导，商品顺带跟着跑”

## 3.2 使用逻辑优先于情绪逻辑

手机挂链的价值优先级应是：

1. 好搭
2. 好拿
3. 好看
4. 解放双手
5. 细节有辨识度

情绪/氛围感只能建立在以上基础成立之后。

## 3.3 单一组图内部必须统一

同一组内：

- 同一人物特征
- 同一服装体系
- 同一商品材质与颜色
- 同一场景逻辑
- 同一视觉方向

禁止同一组出现“运动 + 轻奢 + 秋冬 + 更衣室 + 街头”多风格杂糅。

## 3.4 手机挂链需要独立治理，不再泛化复用

当前很多问题来自：

- 手机挂链直接复用手机壳模板
- 泛类目 Scene / Persona 没做品类级约束
- ShotPlan 只做内容形式，不做商品展示逻辑约束

本次整改要求手机挂链有一套独立治理规则。

## 4. 根因分析

## 4.1 Scene 表当前根因

### 问题 A：场景对“商品展示适配度”没有硬门槛

表现：
- 跑步、瑜伽、飞扬链条、镜前全身、双人互动等模板被允许进入候选池
- 场景强调身体线条/动态氛围，而不是挂链展示

### 问题 B：场景描述中夹带过多性感化身体指令

表现：
- 大量模板含：时尚性感、曲线自然、腿部线条、腰部、迷你裙等描述
- 容易把模型重心带向人物身体，而不是手机挂链

### 问题 C：场景字段缺少“品类适配等级”

当前只有：
- 适用品类
- 平台
- 风格描述

但没有：
- 是否适合手机挂链近景展示
- 是否适合挂接关系展示
- 是否适合实用场景叙事

## 4.2 Persona 表当前根因

### 问题 A：人设风格过于泛化，缺少“品类带货适配”约束

表现：
- 烟熏妆、皮草、薄纱、欧美妆、强街头、大动态动作等人设会被手机挂链命中
- 人设气质与商品风格经常不匹配

### 问题 B：人设只表达“长什么样”，没有强表达“为什么适合卖手机挂链”

缺少字段层面的限制：
- 是否适合通勤/校园/街拍自拍/镜前自拍/包袋配件展示
- 是否适合半身/手持近景
- 是否容易遮挡挂链

## 4.3 ShotPlan 表当前根因

### 问题 A：ShotPlan 设计偏“内容氛围组图”，不偏“商品带货组图”

表现：
- 瑜伽裤、跑步、闺蜜双人、秋冬主题、大片感等镜头结构会稀释商品
- 没有要求 5 张图中必须有几张明确展示挂接点/链条主体/手持关系

### 问题 B：ShotPlan 缺少商品可见度 KPI

当前节点只写“氛围/动作/构图”，没写：
- 商品占比
- 近景数量
- 挂接点可见要求
- 遮挡限制
- 链条完整度

## 4.4 Strategy 表当前根因

当前问题相对较轻，但仍存在：
- 部分策略适用品类过广，手机挂链会命中本来更适合手机壳/其他数码配件的策略
- 缺少“实用/配饰/穿搭/通勤/细节种草”这类手机挂链优先的策略分层

## 4.5 2026-04-21 新增确认的生成链路根因

在后续对 `T_260421_067` 做表3 / 表4 / 本地产物交叉审计后，新增确认以下系统级问题：

### 问题 A：Prompt 记录与最终图片产物可能错位

表现：
- 重跑时会重新分配 `scene / persona / shotplan / brief`
- 表3 Prompt 与 observability 字段会被新值覆盖
- 但表4 若已是“已生成”，当前链路可能直接跳过重生
- 结果形成“新 Prompt + 旧图”的审计错位

### 问题 B：历史内容缺少 Prompt 指纹，无法证明图与 Prompt 的一一对应

表现：
- 旧 `content.json.debug` 中没有 `prompt_fingerprint / brief_fingerprint`
- 重跑前无法自动判断当前 Prompt 是否与历史已生成内容一致
- 会影响回归验证、审计追溯与缓存复用安全性

### 问题 C：Persona 字段注入仍偏软，年龄/穿搭/外貌/一致性约束不够硬

表现：
- `Prompt描述模板` 会折叠细粒度字段
- `穿搭风格` 没有稳定进入人物主锁定块
- 一致性约束多为中文自然语言，未形成图像模型更易遵守的结构化硬约束

### 问题 D：Scene / Persona / ShotPlan 仍可能互相打架

表现：
- `无人物·纯产品` Scene 仍可能叠加强人物 Persona 或人物动作 ShotPlan
- Scene 中残留旧导向（如性感/短裙/腿部线条）会稀释新的人设锁定要求

## 5. 新体系设计（方案 A 的系统化落地）

本节是对先前结论中“手机挂链专用优化方案（A）”的系统化落地。

## 5.1 手机挂链模板白名单体系

### Scene 白名单一级优先

以下场景应作为手机挂链核心白名单：

1. 通勤地铁 / 电梯口 / 闸机前
2. 咖啡店 / 外带咖啡 / 付款取餐
3. 商场镜前 / 店铺镜前自拍
4. 街头站姿 / 坐姿 / 手持半身街拍
5. 校园 / 教室 / 图书馆 / 自习桌
6. 办公桌 / 工位 / 会议间隙 / 通勤路上
7. 包袋搭配 / 出门拿卡 / 翻包 / 拿钥匙
8. 旅行酒店 / 电梯镜 / 出发前收纳
9. 健身后休息区 / 更衣室镜前（仅弱保留）

### Scene 弱保留

可以保留，但需严格约束：

- 健身后更衣室镜前
- 户外休息区 / 拉伸区
- 车内出行（仅静态，不做高级大片路线）

### Scene 禁用或默认下线

- 跑步动态
- 链条飞扬
- 大幅跳跃
- 双人同框主叙事
- 迷你裙/腿部线条导向场景
- 强性感化镜头
- 速度虚化主导场景
- 瑜伽裤专属展示型场景
- 与产品材质不符的季节化大片场景

## 5.2 Persona 白名单体系

### 推荐保留的人设方向

1. 甜酷通勤女生
2. 清冷极简女生
3. 精致都市白领
4. 轻松校园女生（降幼态处理）
5. 轻街头 clean fit 女生
6. 镜前自拍时髦女生
7. 咖啡馆文艺简约女生
8. 包袋配件型穿搭女生

### Persona 需整改方向

- `PS005` 松弛户外女孩：保留“松弛”，去掉过强运动休闲/工装帽子倾向
- `PS012` 氛围感摄影女孩：不再用于手机挂链主链路；若保留，只能用于极少数场景且需改淡妆、轻时尚、非皮草薄纱
- 校园人设：降低“双马尾/过幼态/跑动大笑”权重
- 街拍人设：降低“欧美妆/厚重皮夹克/强风格大片感”

### Persona 禁用信号

如果人设命中以下任一，则默认不进入手机挂链主池：

- 烟熏妆 / 欧美妆 / 皮草 / 薄纱
- 强工装 / 军感 / snapback / 大帽檐遮挡
- 双马尾 / 过度幼态
- 大幅跳动、甩链、奔跑型动作
- 强遮脸 / 半遮脸 / 大片姿态优先

## 5.3 ShotPlan 白名单体系

### 手机挂链标准 5 图骨架（新增主方案）

所有手机挂链种草图文优先采用以下结构：

1. **半身穿搭主图**  
   展示人物精致度、穿搭氛围和手机挂链的自然存在感
2. **手持近景图**  
   明确看清手机壳、挂接点、链条主体、猫咪/珠子细节
3. **使用动作图**  
   拿咖啡 / 刷卡 / 翻包 / 自拍 / 拿钥匙等真实动作
4. **穿搭点睛图**  
   产品与服装、包袋、配件之间形成搭配逻辑
5. **氛围收尾图**  
   保留情绪，但商品仍需清晰可见

### 手机挂链教程/测评骨架（新增）

1. 产品整体
2. 挂接方式特写
3. 手持/腕挂/包袋搭配近景
4. 材质/细节特写
5. 日常使用效果图

### ShotPlan 禁用/下线方向

- 跑步主叙事
- 瑜伽裤展示主叙事
- 双人闺蜜主叙事
- 秋冬厚穿搭泛主题方案
- 金属质感误导型方案
- 大片式黄金时段构图优先于商品展示的方案

## 5.4 Strategy 白名单与扩充方向

### 手机挂链优先策略方向

1. 通勤解放双手型
2. 穿搭点睛型
3. 包袋配件联动型
4. 自拍出片型
5. 细节质感种草型
6. 日常实用型
7. 送礼小物型
8. 校园随手拿型
9. 逛街咖啡轻时髦型
10. 出门收纳效率型

### 低优先或降权策略方向

- 纯专业测评型（仅教程/测评内容保留）
- 极限运动/极限动态场景型
- 过强大片感叙事型

2. 分为：
   - 保留
   - 降权
   - 下线
   - 新增

## 10. 验收标准

### 数据层验收

- 所有手机挂链模板均完成分类
- 高风险模板已被下线或降权
- 新增模板达到规划最低数量的 70% 以上

### 逻辑层验收

- 手机挂链任务命中白名单模板的比例 >= 80%
- 禁用组合（如跑步场景 + 氛围烟熏人设）不再出现
- ShotPlan 中每组图片存在商品近景与挂接展示要求

### 结果层验收

选取不少于 3 个手机挂链任务进行重跑，人工/模型双审：

- 人物精致度明显提升
- 服装时尚度明显提升
- 商品可见度明显提升
- 场景与商品适配明显提升
- “跑步不适合挂链展示”这类问题不再成为主问题

## 11. 风险与注意事项

1. 当前四表数据量较大，不能一次性手工改，必须脚本化
2. 旧模板可能仍被其他品类复用，整改时要避免误伤手机壳主链路
3. 下线过多模板可能导致候选池过窄，必须同步补新增模板
4. 代码过滤逻辑必须与飞书字段实际可读写能力兼容
5. 先完成审计和规划，再执行数据写回，避免反复返工

## 14. 结论

本次整改不是“调几条 prompt”，而是要把手机挂链从“泛品类拼装生成”升级为“有独立治理规则的模板体系”。

核心判断：

> **手机挂链类目已经足够重要，必须拥有独立的策略、场景、shot plan、人设白名单及校验规则。**

只有这样，后续的图片质量、商品突出度、时尚感与可控性，才会稳定提升。
