# 提示词生成全局架构文档

**更新日期**：2026-04-09  
**覆盖范围**：表2（内容规划）→ 表3（Prompt）→ 表4（内容生成），涉及表7/8/9/10 辅助表

---

## 一、整体流程图

```
飞书 表2 内容规划表
│  触发字段：执行状态="待处理"
│
▼
Poller（轮询）→ Dispatcher → ContentGenerationHandler._run()
│
├─ Step 1: 读取表2 plan_record（任务参数）
├─ Step 2: 验证 + 读取表1 SKU记录
├─ Step 3: 解析配置（平台/模型/图数/组数）
├─ Step 4: 从表7 抓取 TOP N 标签
├─ Step 5: 构建 groups（每组=一条内容）
│           每组随机分配 content_type（12种之一）
├─ Step 5a: 从表10 分配视觉场景 → scene_assignments
├─ Step 6: 为每组创建表3 Prompt记录（C后缀=文案，I后缀=图/视频）
│
├─ Step 7: _fill_prompts() — 填写表3 总Prompt
│   ├─ 文案类（suffix=C）
│   │   ├─ 从表8 查匹配策略 _lookup_strategy()
│   │   │   ├─ 有策略 → _build_text_prompts_from_strategy()
│   │   │   │           系统提示词前缀 + 文案叙事节点 → (system, user_prompt)
│   │   │   └─ 无策略 → _build_meta_prompt() 硬编码兜底
│   │   └─ 写入表3 总Prompt（仅写提示词，不调AI）
│   │
│   └─ 图片类（suffix=I）
│       ├─ 从表8 查匹配策略 _lookup_strategy()
│       ├─ 从表9 查匹配拍摄方案 _lookup_shotplan()
│       │   └─ 若返回 None → 使用 _DEFAULT_SHOT_ROLES 6张产品图兜底
│       ├─ _build_image_master_prompt() → 主 Prompt（含场景/风格）
│       ├─ _build_image_sub_prompts() → 子 Prompt 列表（每张图的镜头角色）
│       └─ 写入表3 总Prompt + 子Prompt列表
│
├─ Step 8: 标记表3 所有 Prompt 状态="已确认"
│
├─ Step 9: _generate_content()
│   ├─ 文案：调用 TextModelAdapter → AI 生成标题/正文
│   ├─ 图片：调用 ImageModelAdapter（逐张）→ 生成图片 URL/文件
│   └─ 写入表4 内容生成表
│
└─ Step 10: 更新表2 执行状态="完成"
```

## 二、六张核心表字段说明

### 表1 — SKU表（tblf9FAsQuUzvCzK）

| 字段 | 类型 | 作用 |
|------|------|------|
| SKU编号 | 文本 | 唯一标识，格式 SKU-xxx |
| SKU名称 | 文本 | 产品名称，写入 sku_summary |
| 品类 | 单选 | **关键匹配字段**，用于策略/方案/场景筛选（如"手机链"） |
| 上架状态 | 单选 | 必须="已上架"才允许生成 |
| 关键词 | 文本 | 写入 sku_summary，影响文案方向 |
| 价格区间 | 文本 | 写入 sku_summary |
| 目标人群 | 文本 | 写入 sku_summary |
| 产品卖点 | 文本 | 写入 sku_summary，核心描述字段 |
| 产品图主图URL | URL | 供图片生成时参考 |

### 表3 — Prompt表（tbljMPKdYbGTb1K7）

| 字段 | 类型 | 作用 |
|------|------|------|
| Prompt编号 | 文本 | T_YYMMDD_NNN_img01/vid01 等 |
| 关联规划 | 关联 | 指向表2 |

### 表8 — 内容策略表（tblu2EzR78tWjYf6）

**作用**：控制文案调性/角度，给 LLM 的系统提示词前缀

| 字段 | 类型 | 匹配逻辑 |
|------|------|---------|
| 策略编号 | 文本 | ST001-ST030 |
| 是否启用 | 单选 | **必须="启用"**，否则不参与匹配 |
| 适用内容类型 | 多选 | 与 content_type 比较（12种枚举，见附录） |
| 适用平台 | 多选 | 与 platforms[0] 比较（小红书/得物） |
| 适用品类 | 多选 | 与 SKU.品类 比较 |
| 优先级 | 数字 | 同分时高优先级胜出 |
| 系统提示词前缀 | 长文本 | **核心内容**：写入 LLM system prompt |
| 文案叙事节点 | 长文本 | JSON数组，结构化叙事框架 |

**评分规则**（`_select_best()`）：

```
分值4：内容类型✓ + 平台✓ + 品类✓    （最精准）
分值3：内容类型✓ + 平台✓ + 品类空    （跨品类通用）
分值2：内容类型✓ + 平台空 + 品类空    （跨平台通用）
分值1：三字段均为空                    （全局兜底）
分值0：有字段但不匹配                  （不选）
```

> 若所有记录都是0分 → 返回 None → 走硬编码 `_build_meta_prompt()` 兜底

---

### 表9 — 拍摄方案表（tbl0xCaqru1TjwzK）

**作用**：控制每张图的镜头角色/构图方向，解决"图片同质化"问题

| 字段 | 类型 | 匹配逻辑 |
|------|------|---------|
| 方案编号 | 文本 | SP001-SP019 |
| 是否启用 | 单选 | **必须="启用"** |
| 适用内容形态 | 多选 | 必须包含 `"图片"`（代码传参值） |
| 适用内容类型 | 多选 | 同策略表，12种枚举 |
| 适用品类 | 多选 | 与 SKU.品类 比较 |
| 角色序列 | 长文本 | **核心内容**：JSON数组，每个元素描述一张图的拍摄角色 |

**角色序列 JSON 格式**（当前规范）：
```json
[
  {"index": 1, "shot": "首图人物全身", "desc": "模特全身出镜，手持手机..."},
  {"index": 2, "shot": "人物上半身特写", "desc": "模特上半身，手机握持姿势..."},
  ...
]
```

> ⚠️ 历史格式 `{"zh": "...", "en": "..."}` 也兼容（代码多格式读取）

**匹配流程**（`_lookup_shotplan()`）：
```
1. 过滤 是否启用="启用" 的记录
2. 过滤 适用内容形态 包含 "图片" 的记录
   → 若无匹配，退回全量（兜底逻辑）
3. _select_best() 按 内容类型 + 品类 打分
4. 返回最匹配记录，或 None（触发 _DEFAULT_SHOT_ROLES 兜底）
```

### 表10 — 视觉场景表（tbliWlwiyA4sppgY）

**作用**：给图片生成注入场景基底（背景/风格/色调）

| 字段 | 类型 | 说明 |
|------|------|------|
| 场景编号 | 文本 | SC001-SC028 |
| 是否启用 | 单选 | 必须="启用" |

| 风格基调词 | 文本 | 注入 master_prompt |
| 排除描述 | 文本 | 注入 negative_prompt |

## 四、常见失效模式与排查

| 症状 | 可能根因 | 排查方法 |
|------|---------|---------|
| 图片全是极简背景主体图 | 表9 返回 None → `_DEFAULT_SHOT_ROLES` 兜底 | 检查 SP 记录的是否启用/适用内容形态/适用内容类型 |
| 文案标题重复/无差异化 | 表8 策略匹配失败 → 硬编码兜底 | 检查 ST 记录的适用内容类型是否在12种枚举内 |
| 新类目策略不生效 | 适用品类字段为空或错填 | 对照 SKU.品类 字段值精确填写 |
| 策略/方案新增后不生效 | 是否启用≠"启用" | 飞书表中修改后需重启或等下次轮询 |
| 场景描述未注入图片 | `{scene_description}` 占位符未在节点 desc 中使用 | 在拍摄方案 desc 字段中加入 `{scene_description}` |

## 五、CONTENT_TYPES 枚举（12种）

这是系统内部使用的枚举值，表8和表9的`适用内容类型`字段**必须**精确使用这些值：

```
种草推荐 / 好物分享 / 深度测评 / 对比测评
穿搭搭配 / 场景展示 / 日常vlog
开箱 / 买家秀/晒单 / 节日/活动限定 / 新品发布
选购攻略/使用教程
```
