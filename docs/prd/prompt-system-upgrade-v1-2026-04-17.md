## 1. 背景与问题定义

AI-Content-Hub 当前已具备以下能力：
- 表2 规划表触发任务
- 表8 Strategy 控制文案叙事
- 表9 ShotPlan 控制图片镜头分工
- 表10 Scene 控制视觉场景
- 表3 存储 Prompt
- 表4 存储最终生成内容

现阶段系统能跑通，但在内容质量控制上存在以下瓶颈：

### 1.1 当前主要问题

1. **Prompt 仍然是“拼装式”生成**
   - 当前主要是 SKU + Strategy + Scene + ShotPlan 直接拼接
   - 文案和图片虽然共享部分输入，但缺少统一中间语义层
   - 导致“文案意图”和“图片意图”有时并不完全一致

2. **多组内容差异性还不够系统化**
   - 当前已有标题句式轮转、prior_titles 防重复、场景切换等能力
   - 但仍缺乏明确的“叙事角度”“人设角度”“画面构图角度”控制

3. **图片组内一致性需要进一步稳固**
   - 当前已加入人物外貌锚点、一致性约束
   - 但还没有把“组内强一致 / 组间弱差异”显式建模

4. **场景与人物扩展仍主要靠单表堆字段**
   - 目前 Scene 表承担过多职责：场景、人物、技术参数、排除项都放在一起
   - 不利于后续系统化扩展“人物模板”

5. **可观测性不足**
   - 现在生成结果可以落地，但很难快速回答：
     - 某组内容用了哪条策略？
     - 某组图片用了哪个场景？
     - 为什么这组和另一组差异不明显？
     - 某次失败发生在哪张图、哪一步？

## 2. 本次升级目标

### 2.1 总目标

把当前 Prompt 系统从“能生成内容”升级为“**可控地产生差异化内容，并具备调优抓手**”的系统。

### 2.2 本次必须达成的目标

1. 新增 **Creative Brief（创意包）层**，作为文案 Prompt 与图片 Prompt 的统一中间层
2. 支持更丰富的人设来源与人物控制
3. 支持更强的多组差异化控制
4. 支持更明确的组内一致性约束
5. 增加 Prompt 命中链路和生成结果的可观测字段
6. 保持当前单平台、飞书驱动、轮询执行架构不变

### 2.3 本次明确不做

1. 不做多平台任务拆分
2. 不把标签注入 Prompt
3. 不围绕“转化率”“成交率”“CTA优化”做策略设计
4. 不把系统改造成事件流 / MQ / 微服务架构
5. 不重构 Poller / Dispatcher 主体模式

## 3. 本次升级范围

本次升级覆盖以下模块：

### 3.1 业务配置层
- 表8：内容策略表（扩展）
- 表9：ShotPlan 拍摄方案表（扩展）

### 3.3 Prompt 生成层
- 文案 Prompt 由 Brief + Strategy 共同生成
- 图片 Master Prompt 由 Brief + Scene + Persona 共同生成
- 图片 Sub-Prompt 由 Brief + ShotPlan 共同生成

### 3.4 可观测性层
- 表3 Prompt 表增加命中与调试字段
- 表4 内容表增加结果侧观察字段
- `plan.json` / `content.json` 扩展元数据

## 4. 升级后的核心设计

## 4.1 新增 Creative Brief 层

### 定义
Creative Brief（创意包）是每个 group 在生成 Prompt 前先得到的一份结构化意图对象。

### 作用
它不是给最终用户看的，也不是直接给飞书运营编辑的，而是：
- 统一文案和图片的内容意图
- 统一差异化控制来源
- 统一一致性约束来源
- 为可观测性提供结构化依据

### Brief 样例

```json
{
  "group_id": "img01",
  "platform": "得物",
  "content_type": "种草推荐",
  "narrative_angle": "搭配点睛",
  "narrative_structure_mode": "场景切入",
  "title_pattern": "疑问句式",
  "persona_label": "甜酷通勤女生",
  "persona_anchor": "22-26岁，长发，轻妆，甜酷风，轻松自然",
  "scene_mode": "商场通勤轻时髦",
  "scene_id": "SC018",
  "shotplan_id": "SP014",
  "strategy_id": "ST026",
  "consistency_anchor": {
    "person": "同一女生，同套服装，同款发型，同一面部特征",
    "product": "同一颜色、同一材质、同一挂接方式",
    "style": "统一光线、统一色温、统一画面风格"
  }
}
```

### 设计要求
1. 每个 group 必须有且仅有一个 Brief
2. Brief 必须在 Prompt 生成前完成
3. Brief 必须可落地到：
   - 表3 调试字段
   - 本地 `plan.json`
   - 本地 `content.json`
4. Brief 可由代码生成，不要求人工在飞书中直接编辑

---

## 4.2 差异性升级原则

### 原则一：组内强一致
同一 group 内的图片必须像同一次拍摄：
- 同一人物
- 同套服装
- 同款发型
- 同一产品细节
- 同一视觉风格

### 原则二：组间弱差异
不同 group 之间应像不同内容企划：
- 可以换人物模板
- 可以换场景
- 可以换叙事切入角度
- 可以换标题句式
- 可以换镜头组织方式

### 原则三：差异性必须显式建模，不依赖模型“自己发挥”
差异性不再只靠：
- 标题句式轮转
- prior_titles 注入

而是扩展为 4 个维度：
1. **叙事角度差异**
2. **叙事结构差异**
3. **人设差异**
4. **视觉构图差异**

## 5. 升级后的表格流转

## 5.1 总体流转图

```text
表2 内容规划表
  ↓ 触发
Poller → Dispatcher → ContentGenerationHandler
  ↓
读取 SKU / 计划配置
  ↓
读取标签（保留原逻辑，不进 prompt）
  ↓
构建 groups
  ↓
分配 Scene
  ↓
匹配 Persona（新增）
  ↓
匹配 Strategy
  ↓
匹配 ShotPlan
  ↓
为每个 group 构建 Creative Brief（新增核心步骤）
  ↓
写入表3 Prompt 记录（总Prompt、子Prompt、命中信息、创意包摘要）
  ↓
调用文案/图片模型生成内容
  ↓
写回表4 内容记录（标题、正文、图片、命中信息、失败原因等）
  ↓
本地 plan.json / content.json 补充完整观察信息
```

## 5.2 Brief 驱动后的 Prompt 生成关系

```text
Strategy  ─┐
Scene     ─┼─> Creative Brief ──> 文案 Prompt
Persona   ─┤
ShotPlan  ─┘                  └─> 图片 Master Prompt + Sub-Prompts
```

## 6. 表格与字段调整说明

# 6.1 表2：内容规划表（调整）

### 调整原则
- 保持现有任务触发逻辑
- 不增加复杂的运营负担
- 只补充“允许 AI 更好做差异化控制”的少量配置项

### 新增字段

| 字段名 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---:|---|---|
| 差异化强度 | 单选 | 否 | 中 | 低 / 中 / 高。用于控制多组内容差异程度 |
| 人设模式 | 单选 | 否 | 自动 | 自动 / 固定主人设 / 多人设轮换 |
| 一致性强度 | 单选 | 否 | 强 | 中 / 强。控制组内图片一致性约束力度 |
| 场景丰富度 | 单选 | 否 | 中 | 低 / 中 / 高。影响场景切换幅度 |

### 字段业务逻辑

1. **差异化强度**
   - 低：保守，少量变化
   - 中：默认，标题、人设、角度适度变化
   - 高：尽可能拉开不同 group 的内容风格差异

2. **人设模式**
   - 自动：系统自动分配 persona
   - 固定主人设：整单使用同一 persona 主模板
   - 多人设轮换：不同 group 轮换 persona

3. **一致性强度**
   - 强：组内所有图必须强一致
   - 中：允许轻微姿态、动作、构图变化，但人物身份不变

4. **场景丰富度**
   - 低：相近场景切换
   - 中：中等范围切换
   - 高：不同视觉场景之间更明显变化

# 6.2 表3：提示词生成表（调整）

### 调整目标
增加 Prompt 可观测性，便于回溯“这一条 Prompt 是如何形成的”。

### 新增字段

| 字段名 | 类型 | 说明 |
|---|---|---|
| 创意包摘要 | 长文本 | 存储当前 group 的 Creative Brief 摘要（可读版） |
| 创意包JSON | 长文本 | 存储结构化 Brief JSON |
| 命中策略ID | 文本 | Strategy record_id 或 业务编号 |
| 命中场景ID | 文本 | Scene record_id 或 场景编号 |
| 命中人设ID | 文本 | Persona record_id 或 人设编号 |
| 命中ShotPlanID | 文本 | ShotPlan record_id 或 方案编号 |
| 标题句式 | 文本 | 如：疑问句式 / 反转句式 |
| 叙事角度 | 文本 | 如：搭配点睛 / 日常分享 / 质感细节 |
| 一致性锚点 | 长文本 | 本组图片一致性约束文字摘要 |
| 是否兜底生成 | 单选 | 是 / 否；表示是否命中默认逻辑而非配置逻辑 |

### 字段写入规则

1. `_fill_prompts()` 完成时写入上述字段
2. 若某维度未命中配置表，必须明确写入“兜底”信息，而不是留空
3. `创意包JSON` 用于调试和后续分析，不要求运营直接编辑

# 6.4 表8：内容策略表 Strategy（扩展）

### 调整目标
让 Strategy 不再只定义“叙事节点”，而是承担“内容差异化策略模板”的职责。

### 保留字段
- 适用内容类型
- 适用平台
- 适用品类
- 优先级
- 系统提示词前缀
- 文案叙事节点
- 标题写作指南
- 情绪基调

### 新增字段

| 字段名 | 类型 | 说明 |
|---|---|---|
| 叙事角度标签 | 多选 | 如：搭配点睛 / 日常实用 / 细节质感 / 氛围感 / 礼物感 |
| 结构模式 | 单选 | 痛点切入 / 场景切入 / 体验切入 / 对比切入 / 情绪切入 |
| 标题句式池 | 长文本 | JSON 数组，允许比当前硬编码更灵活 |
| 正文禁忌 | 长文本 | 禁止出现的表达，例如过硬广告腔 |
| 差异化提示模板 | 长文本 | 对当前篇次的差异化要求模板 |
| 人设适配标签 | 多选 | 表示该策略更适合哪些 persona 类型 |

### 示例

`标题句式池` 示例：
```json
[
  "疑问句式",
  "数字/对比句式",
  "场景直述句式",
  "反转句式",
  "情绪共鸣句式"
]
```

### 业务规则
1. 若 `标题句式池` 有值，则优先使用表内配置，而不是代码硬编码默认池
2. 若 `差异化提示模板` 有值，则用于替换默认的篇次差异化提示
3. 若 `人设适配标签` 有值，Brief 选 persona 时应优先命中相容人设

| 人物出镜比例 | 单选 | 无人物 / 少量 / 中等 / 高 |

# 6.7 表12：Persona 人设模板表（新增）

## 新增原因
目前人物描述主要依赖 Scene 表字段，扩展性不足。需要单独的人设模板层来支持：
- 丰富人物风格
- 支持同 SKU 多组内容切换不同人设
- 与 Strategy / Scene 做软匹配
- 提升可观测性

## 表名
**表12：Persona 人设模板表**

## 字段设计

| # | 字段名 | 类型 | 说明 |
|---|---|---|---|
| 1 | 人设编号 | 文本 | 如 PS001 |
| 2 | 是否启用 | 单选 | 启用 / 停用 |
| 3 | 人设名称 | 文本 | 如：甜酷通勤女生 |
| 4 | 性别倾向 | 单选 | 女 / 男 / 中性 |
| 5 | 年龄段 | 单选 | 18-22 / 22-26 / 26-30 / 30+ |
| 6 | 外貌风格 | 文本 | 如：长发、轻妆、甜酷感 |
| 7 | 穿搭风格 | 文本 | 如：休闲通勤 / 极简时髦 |
| 8 | 气质标签 | 多选 | 甜酷 / 清冷 / 松弛 / 精致 / 青春 |
| 9 | 动作倾向 | 文本 | 如：自然持握、回头、低头看手机 |
| 10 | 适用品类 | 多选 | 手机链 / 手机壳 / 通用 |
| 11 | 适用内容类型 | 多选 | 种草推荐 / 穿搭搭配 / 场景展示 等 |
| 12 | 适合场景标签 | 多选 | 商场 / 校园 / 咖啡馆 / 街头 等 |
| 13 | Prompt描述模板 | 长文本 | 用于生成 persona_anchor |
| 14 | 一致性锚点模板 | 长文本 | 用于生成组内人物一致性约束 |
| 15 | 优先级 | 数字 | 同类候选中排序 |
| 16 | 备注 | 文本 | 说明 |

## 使用规则
1. Persona 是 **组级别** 选择，不是图片级别选择
2. 同一 group 内所有图片共享同一 persona
3. 当表2 `人设模式=固定主人设` 时，整单共享同一 persona
4. 当表2 `人设模式=多人设轮换` 时，不同 group 可轮换 persona
5. 若未命中 Persona，回退到 Scene 中已有人物字段

## 7. 升级后的核心业务逻辑

# 7.1 ContentGenerationHandler 新流程

原流程基础上新增以下阶段：

```text
1. 读取 plan / sku / cfg
2. 取 tags（保持原逻辑）
3. build_groups()
4. assign_scenes()
5. lookup_persona()         ← 新增
6. lookup_strategy()
7. lookup_shotplan()
8. build_creative_brief()   ← 新增核心步骤
9. fill_prompts_from_brief()
10. generate_content()
11. write observability fields
12. 更新 plan 状态
```

---

# 7.2 Brief 生成规则

每个 group 的 Brief 至少包含：
- 平台
- 内容类型
- 命中 strategy
- 命中 scene
- 命中 persona（若无则 fallback）
- 命中 shotplan
- title pattern
- narrative angle
- structure mode
- consistency anchor

### 差异性生成规则

在同一任务的多个 group 中，系统必须优先拉开以下项目：

1. `title_pattern`
2. `narrative_angle`
3. `persona_label`（若人设模式允许）
4. `scene_mode`
5. `shot_style` / `构图节奏`

### 建议顺序
- 先保证标题与叙事角度不同
- 再保证场景与人物不同
- 最后再通过镜头差异拉开图片表现

---

# 7.3 文案 Prompt 生成规则

文案 Prompt 由以下信息共同构成：
- Strategy 的系统提示词前缀
- Brief 中的叙事角度
- Brief 中的结构模式
- Brief 中的标题句式
- Scene 的场景中文描述
- Persona 的人物感觉（必要时进入语境描述）
- 篇次差异化说明
- prior_titles 防重复约束

### 要求
1. 文案 Prompt 必须体现“当前篇次的独特角度”
2. 文案 Prompt 必须使用 Brief 中明确选定的 `narrative_angle`
3. 若 Strategy 未提供角度字段，代码可回退到默认角度池
4. 标签不进入文案 Prompt

---

# 7.4 图片 Prompt 生成规则

## Master Prompt
应包含：
- 产品描述
- 场景描述
- 人设描述 / persona anchor
- 组内一致性约束
- 风格和技术参数
- 道具建议（若有）

## Sub-Prompt
应包含：
- 当前镜头角色
- 当前镜头动作说明
- 当前构图节奏约束
- 当前人物动作变化
- 场景补充说明
- 一致性锚点提示

### 要求
1. 组内每张图都必须附带一致性锚点
2. 不同图之间必须尽量避免重复构图
3. 若 ShotPlan 有“禁止重复镜头”字段，则必须参与 sub-prompt 生成
4. 若 Persona 存在，则人物锚点优先来自 Persona，而不是 Scene

## 10. 验收标准

### 10.1 功能验收

1. 能为每个 group 构建 Creative Brief
2. 表3 能落创意包与命中信息
3. 表4 能落生成链路调试信息
4. 新增 Persona 表后，可按 plan 配置实现：
   - 自动人设
   - 固定主人设
   - 多人设轮换
5. 文案 Prompt 能显式体现叙事角度与标题句式
6. 图片 Prompt 能显式体现 persona anchor 与一致性锚点

### 10.2 质量验收

1. 同一任务 3 组图文内容，标题句式不完全重复
2. 同一任务 3 组图文内容，正文叙事切入角度至少有 2 组不同
3. 同一组 5 张图片，人物主特征保持一致
4. 表3 / 表4 / 本地 JSON 中可追踪每组命中的配置来源

### 10.3 回归验收

1. 不影响现有 AI全创作 主链路
2. 不影响图片实拍+AI文案、视频实拍+AI文案 主链路
3. 不影响发布链路
4. 不影响标签写回逻辑

## 12. 风险与注意事项

1. **飞书字段新增后，代码必须容忍字段尚未建立的阶段**
2. **Persona 表是新增表，system.yaml 和同步逻辑也要补充**
3. **观测字段不要过多影响运营视图，可优先放在表3、表4尾部或本地 JSON**
4. **不要把“可观测性”做成影响主流程成功率的硬依赖**
5. **差异化增强不能以牺牲可控性为代价**，避免生成过于发散的内容

## 14. 总结

本次升级不是重做架构，而是在保持当前飞书驱动内容中台不变的前提下，补齐 Prompt 系统最关键的四件事：

1. **加入 Creative Brief 中间层**
2. **加入 Persona 人设模板能力**
3. **系统化提升差异性与一致性控制**
4. **补齐可观测性**

目标不是让系统“更复杂”，而是让系统：
- 更容易扩展场景和人物
- 更容易拉开多组内容差异
- 更容易维持组内图片一致
- 更容易排查问题和做后续优化

---

**建议开发顺序**：
1. 先加 observability 字段与本地 JSON 扩展
2. 再加 Brief 层
3. 再接 Persona 表
4. 最后调整 Strategy / Scene / ShotPlan 的增强字段使用
